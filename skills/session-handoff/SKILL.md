# 인계 프롬프트 작성

대상: `$ARGUMENTS`

> **목표**: 받는 세션은 대화 맥락을 모른다. **이 문서 하나만 읽고** 착수할 수 있어야 한다 — 관련 파일과 인터페이스를 이름으로 적고, 범위 밖을 밝히고, 끝-끝 검증 단계로 마무리한다.
> 프로젝트에 인계 문서 양식·위치 규약이 있으면 그쪽을 따른다. 이 스킬은 없을 때의 기본값이다.

## 저장 위치 (프로젝트 규약이 없을 때)

- 태스크 폴더(`/task-folder`)가 있으면 `<태스크 폴더>/handoff/YYYY-MM-DD-<주제>.md`
- 없으면 프로젝트의 태스크 문서 디렉토리 옆, 그것도 없으면 사용자에게 1회 확인한다.
- 다른 레포 세션에 넘길 때도 파일은 **작성 중인 레포**에 두고, 받는 쪽이 읽을 상대 경로를 적는다.

## 작성 원칙

1. **사실과 가설을 분리한다** — 확인한 것은 `파일:라인`·명령·확인 시각을 붙이고, 확인 못 한 것은 "가설 — 재검증 후 확정"으로 표시한다. 받는 세션은 가설을 사실로 믿는 순간 틀린다.
2. **이미 확인된 사실은 "다시 조사하지 마라"로 명시**한다 — 받는 세션의 컨텍스트를 아낀다. 단 결론이 걸린 값은 받는 쪽이 1회 재확인하도록 적는다.
3. **대형 문서는 절을 지정**한다 — "문서 정독"이 아니라 "§0 + §3.2만"처럼. 전문 Read를 유발하지 않는다.
4. **브랜치·커밋·push·머지·배포 상태는 git 실측으로** 적는다 (`git log --oneline -3`, `git status`, 원격 존재 여부). "push 안 했다"가 인계 사고의 1순위다.
5. **한계를 마지막에 쓴다** — 이 문서가 모르는 것, 뒤집히면 결론이 바뀌는 것.
6. 작성자만 볼 메모는 맨 끝 `## 전달자 메모 (프롬프트에 포함하지 않음)`에 분리한다.

## 템플릿

```markdown
# 인계 프롬프트 — <작업명> <이번 단계>

> 작성: YYYY-MM-DD HH:MM · 작성 세션 브랜치: `<branch>`
> 한 줄 요약: <받는 세션이 해야 할 일>

## 0. 가장 먼저 (순서 고정)
1) **브랜치** — `git switch <branch>` · 현재 커밋 `<sha>` · push 여부: <예/아니오>
2) **읽을 것** — `<문서 경로>`의 <절만>
3) **규약** — 프로젝트 `CLAUDE.md` (다른 레포가 걸리면 그 레포의 `CLAUDE.md`도)

## 1. 무엇을 하는 작업인가
- 목표:
- 이번 세션의 산출물: (코드 / 문서 갱신 / 질의서 등)
- **범위 밖**:

## 2. 현재 상태 (YYYY-MM-DD 실측)
- 완료:
- 배포 상태:

## 3. 이미 확인된 사실 — 다시 조사하지 마라
| 사실 | 근거 (파일:라인 / 명령 / 원문) |
|---|---|

## 4. 착수 전 해소할 것 (차단 · 결정 필요)
| # | 질문 | 누구에게 | 권장 디폴트 | 답에 따라 달라지는 것 |
|---|---|---|---|---|

## 5. 작업 순서 (권장)
1.

## 6. 코드 착점 (실측)
- `path/to/file` › `symbol` (~N행) — 무엇을 바꾸는가

## 7. 금지 · 주의
- (직전 세션에서 실제로 물린 것 위주)

## 8. 검증 (DoD)
- (실제로 돌릴 수 있는 명령)

## 9. 응답 규약
- 받는 세션이 끝나면 보고할 형식 (변경 파일 · 검증 결과 · 남은 질문)

## 이 문서의 한계
- 확인하지 못한 것 / 가설인 것 / 뒤집히면 달라지는 것
```

**다른 레포 세션용**이면 2절을 "이쪽이 제공하는 것"(인터페이스·요청/응답 필드·에러·상태 전이, 정본이 어느 쪽인지)으로, 3절을 "그쪽 현재 상태 — 직접 확인한 것"으로 바꾸고 배포 순서를 추가한다.

## 쓰고 나서 확인

- [ ] 0절만 보고 브랜치·읽을 것·규약을 알 수 있다
- [ ] 모든 "사실"에 근거가 붙어 있고, 가설은 가설로 표시돼 있다
- [ ] 범위 밖이 적혀 있다
- [ ] 검증 명령이 실제로 돌릴 수 있는 형태다
- [ ] 한계 절이 비어 있지 않다 (없으면 "없음 — 이유")
